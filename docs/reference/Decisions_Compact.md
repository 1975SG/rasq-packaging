# IDERM -- Architecture Decision Records, compacted index

One line per decision. Canonical detail, full context, and consequences live in `docs/Decisions.md` (not part of this doc set) -- this index exists for a reader who wants the shape of the whole project without reading 77 full entries.

| ADR | Decision |
|---|---|
| ADR-001: Core implementation language | Rust: direct access to the existing terminal/async OSS ecosystem, memory safety for concurrent PTY/render/scan workloads; trades off C++ contributors for reach. |
| ADR-002: No GUI toolkit (Qt rejected) | Terminal is the entire application surface (ratatui + crossterm); single static binary, no windowing dependencies. |
| ADR-003: Editing engine is embedded, not authored | Embed Neovim rather than write a buffer/undo/tree-sitter stack from scratch (Atom's own failure mode). |
| ADR-004: Interaction model is block-mode, not stream-mode | Tree/doctor/build panels use IBM-3270-style full-screen atomic redraw with protected fields, not incremental VT100 redraw; retro theming is opt-in only. |
| ADR-005: Mouse support is additive, never primary | SGR mouse protocol drives click actions; every mouse action must have a keyboard equivalent, no exceptions. |
| ADR-006: Language and rule support is a plugin concern, not core | Core ships language-agnostic; a plugin manifest declares detection/build/LSP/grammar per language -- the primary OSS-contribution surface. |
| ADR-007: Plugin ABI/SDK | Hybrid: manifests and already-standardized tools (LSP, build tools) run as native subprocesses; doctor rules/repair recipes run sandboxed as WASM components via a versioned WIT interface. |
| ADR-008: Headless interface precedes AI | JSON output ships before any AI subcommand; AI consumes it exactly like any external tool, no privileged shortcut. |
| ADR-009: Workbench plugin category -- `view-provider` | Adds a third WASM plugin category for interactive visualization panels; the interface shape itself deferred to ADR-014. |
| ADR-010: License boundary for domain-specific workbench plugins | A workbench plugin wrapping copyleft-licensed code ships as its own separately-licensed package, never merged into core; core stays MIT/Apache-2.0 unconditionally. |
| ADR-011: Sensitive-concept exclusion | No non-public consuming project or use case is ever named in docs or git history; capabilities are described generically, permanently, not "not yet." |
| ADR-012: OSS publication gate | Repositories go public only once workbenches ship AND a real end-to-end test suite exists -- both conditions required, neither alone sufficient. |
| ADR-013: WIT plugin ABI versioning policy | Semver policy for the plugin ABI (PATCH/MINOR/MAJOR) with real load-time enforcement; a MAJOR mismatch is rejected outright, MINOR stays additive-safe. |
| ADR-014: `view-provider` interface shape -- three composable primitives | Box-drawing diagrams, a braille curve canvas, and a half-block heatmap grid; a plugin owns its own free-text command vocabulary; 3D visualization explicitly out of scope. |
| ADR-015: Idermviz composition -- shape-overlay data scope | Shape overlays draw on top of grid data; Core stays format-agnostic (SVG/CSV convenience parsers only, no domain formats like Gerber). |
| ADR-016: Multi-pane split view -- up to 4 panes | A small, fixed set of layout templates (Single/Split2/Split3/Grid2x2), not open-ended tiling; `Tab` cycles focus. |
| ADR-017: `xy-chart` statistical bands | One additive WIT record (`band`: upper/lower/label/status) for confidence intervals and percentile ranges, shared across every workbench needing one. |
| ADR-018: Figure Export -- Core-side, SVG + TikZ, PDF excluded | Core (not sandboxed itself) renders exports directly, no new plugin ABI surface; PDF/LaTeX-compile explicitly excluded, revisit only if a real need is named. |
| ADR-019: `deviation-analyzer` -- a shared library crate between plugins | First precedent for plain-Rust code shared *between* plugin crates; residuals/correlation/confidence band, explicitly documented as a heuristic, not rigorous statistics. |
| ADR-020: `distribution-analysis` -- histogram, empirical CDF, linear fit | Second shared crate, feeds `deviation-analyzer`'s fit-overlay need directly; deterministic synthetic sampling via a hand-rolled PRNG, no external `rand` dependency. |
| ADR-021: ABI/contract smoke test -- `example-doctor-abi-smoke-test` | Static-only doctor rule detecting a `static_assert(sizeof(...))` pattern in C/C++ source; silent (no finding) for a non-C/C++ project. |
| ADR-022: `example-view-risk-band` -- P10/P50/P90 fan chart | View-only plugin using percentile-based bands over a synthetic Monte Carlo ensemble; adds `percentile()` to `distribution-analysis`. |
| ADR-023: Language support as a TOML manifest | Replaces a closed 4-variant enum with a TOML-driven `LanguageManifest`; `.iderm/languages/*.toml` becomes a real community-extension point, no Core rebuild needed. |
| ADR-024: `repair-recipe` host loader -- closes out Phase 4 | WASM-proposed repairs, new-file creation only (no diff/patch application yet); a deliberate path-traversal attack was built and confirmed refused. |
| ADR-025: `checksums` -- CRC/checksum tools | Shared crate: CRC-32, two distinct CRC-16 variants, and the Internet checksum, each verified against published reference check values. |
| ADR-026: Invariant checker panel -- `invariant-report` | New plain-text intermediate format for model-checker output that any real checker's own tooling can translate into; both doctor-rule and view-provider built; deliberately not live-refreshed. |
| ADR-027: Channel/interference sanity-checker -- `example-doctor-channel-budget` | Doctor-rule checking declared RF duty-cycle budgets against real regulatory sub-band limits, three severity tiers. |
| ADR-028: Hardware/instrumentation diagnostic workbench -- read-only, subprocess-owned device access | Design only: all device I/O goes through an existing external CLI tool as a subprocess, never a new host import; read-only by construction, device control explicitly deferred, possibly permanently. |
| ADR-029: Logic/Protocol Capture Viewer v1 -- `vcd-parser`, static capture files only | New crate parsing VCD (IEEE 1364/1800) digital-signal captures; reads an already-captured file only, live capture deferred to a v2 mechanism. |
| ADR-030: Core-side capture manager -- generalized as custom project tasks | No capture-specific mechanism built; reuses/extends the existing project task runner (`.iderm/tasks.toml`) plus an automatic rescan once a task finishes. |
| ADR-031: Analog Waveform Viewer v1 -- `analog-waveform` | New crate parsing a generic header-plus-numeric-rows CSV shape, not any one vendor's export dialect; both doctor-rule and view-provider built. |
| ADR-032: Continuous tasks -- one-shot vs continuous, split explicitly | New `TaskMode` (`OneShot`/`Continuous`); a continuous task spawns detached with no terminal handover, tracked and reaped on toggle or app exit -- the one mechanism every live-instrument connectivity type needs, regardless of link type. |
| ADR-033: `heatmap-view` gains an explicit `rgb` cell arm | New WIT variant lets a plugin hand Core an arbitrary per-cell RGB color directly, not only a normalized scalar through a fixed colormap -- unblocks color-accurate and discrete-state use cases without Core taking an opinion on specific palettes. |
| ADR-034: `colorspace` crate -- first `rgb` heatmap consumer | CIE Lab-to-sRGB conversion with an explicit gamut-honesty check that flags a clamped/out-of-gamut color instead of silently clamping it. |
| ADR-035: `halftone` crate -- screening/moiré | Classic amplitude-modulated halftone screening math; checks moiré risk between declared screen angles against real print-industry reference angles. |
| ADR-036: `cellular-automaton` crate -- a genuinely live simulation | Generic totalistic 2D cellular automaton; the one view in this project that actually steps its own simulation forward on every live-refresh tick, rather than re-reading a file. |
| ADR-037: Phase D -- `docs/90-user/`, project-wide | New per-plugin user-guide directory covering every example plugin, not only the one category that first asked for it; every fact checked against real code/output before writing. |
| ADR-038: `frame-format` crate -- byte-level frame/packet builder-inspector | Fixed-width-field packing with explicit endianness plus a checksum trailer (reuses the `checksums` crate); an inspector reports a mismatch rather than refusing to look. |
| ADR-039: `link-graph` crate -- latency/bandwidth/reliability routing | Three genuinely different graph-optimization objectives over one topology, solved as three distinct Dijkstra-style algorithms rather than one algorithm misapplied three ways. |
| ADR-040: `black-scholes` crate -- option-pricing surface | Standard closed-form option pricing, verified against a textbook reference case and put-call parity; renders on the pre-existing scalar heatmap arm, zero Core changes. |
| ADR-041: `potential-flow` crate -- flow-field visualizer | Closed-form 2D potential flow past a cylinder, not a numerical CFD solver; verified against real textbook properties (surface-speed doubling, exactly two stagnation points). |
| ADR-042: Phase 5 v1 -- headless JSON output, instrumented prototype | `scan --format=json` / `doctor --json` ship as a deliberately provisional prototype, used internally first to let real usage -- not speculation -- decide the eventual locked schema. |
| ADR-043: Testbench emulators -- behaviorally-realistic synthetic capture sources | Continuous synthetic emulators for the VCD/analog/frame formats with real injected anomalies (dropped samples, corrupted bits); explicitly still not real hardware. |
| ADR-044: Phase 5 headless JSON schema -- locked in | Versioned envelope, canonicalized root path; the plugin-facing WIT shape and headless JSON are confirmed as permanently separate, independently-versioned schemas after real multi-consumer usage needed no convergence. |
| ADR-045: Run Ledger -- schema-unified with headless JSON | Provenance log (project state, version/os/arch/timestamp/note) appended only via an explicit record command, never a side effect of a read-only scan or doctor run. |
| ADR-046: Figure Export caption -- wired to the Run Ledger | Exporting a figure now pulls the most recent ledger entry's note as its caption, closing a gap left open on purpose until the Run Ledger existed. |
| ADR-047: Standalone CI binary/crate -- decided against, for now | Explicit, reasoned deferral rather than silent ambiguity: a real fix needs a feature-flag or workspace split; the existing headless JSON flags already work today on the one full binary. |
| ADR-048: Dependency/build graph export -- DOT and Mermaid | Pure-text graph export from real build-manifest data only, no invented dependency analysis; verified through a real Graphviz render. |
| ADR-049: Run Ledger diff -- real compare, replay explicitly out of scope | Structural diff between two ledger snapshots; replay would need a different action-log data model, named as real, separate, unscoped work rather than silently implied by "diff." |
| ADR-050: Public doctor-rules repo -- private pre-OSS scaffold | Real per-rule, independently ABI-pinned scaffold repo created private on the account already designated for the eventual public home; goes public only once Core itself does. |
| ADR-051: 8-hour soak test -- real headless CLI under sustained load | Closes the publication gate's test-suite requirement with a real, reproducible 8-hour run: zero errors across 480 ticks under continuous concurrent synthetic load. |
| ADR-052: `.iderm/` config spec + AI Adapter -- the last phase closes | Explicit shareable-vs-local split for `.iderm/` contents; the AI Adapter is model-agnostic by construction, piping JSON to any externally-configured CLI over stdio -- same trust model as any other subprocess tool. |
| ADR-053: `--help`/`-h` had no handling at all | Real gap found live: every invocation with `--help` silently misbehaved instead of erroring or helping; fixed at both the global and per-subcommand level. |
| ADR-054: unhandled no-terminal case crashed with a raw Rust error | Found on real hardware; now prints a clear, actionable message and exits cleanly instead of dumping an unformatted internal error. |
| ADR-055: a capture-reading view never actually live-refreshed | First real (non-emulated) hardware capture exposed a stale "this file never changes" assumption; fixed to re-read and re-parse fresh on every live tick. |
| ADR-056: manual table snapshot + manual data-entry command | One key dumps the focused pane's current table into the log; a typed command lets a user inject a manually-observed reading, validated against non-finite/unknown-channel/outlier values before it can reach a chart. |
| ADR-057: full live-refresh audit across every view plugin | Audited every view plugin for the same stale-assumption class as ADR-055; two more genuinely needed the identical fix, the rest confirmed correctly static for real, named reasons. |
| ADR-058: pinning a pane to one specific capture stream by name | Real multi-stream dogfooding found panes silently rendering the wrong file once several streams coexisted; added an explicit per-pane stream-selection command. |
| ADR-059: durable per-stream event log for continuous tasks | Starting or stopping a continuous task now writes a real start/stop log file per run, using a hand-rolled UTC date algorithm rather than adding a date/time dependency. |
| ADR-060: capture scripts auto-discovered as continuous tasks | Any conventionally-named capture script at the project root is auto-wired into a continuous task with zero manual config; scoped deliberately to discovery only, never interpretation of what a script measures. |
| ADR-061: a bespoke rendering for one specific real-world stream | A dedicated plugin recognizing a capture by its real channel shape (not filename), composed entirely from existing chart primitives -- a rendering choice, not a new capability. |
| ADR-062: synchronized group actions across split-view panes | Group-level live-toggle and timestamped snapshot apply to every pane at once, each with a `Ctrl+Shift+<letter>` fallback for terminals or keyboards that intercept the bare function key. |
| ADR-063: Doctor default ruleset scoped + LSP language roadmap trimmed | Scopes the next work batch; a proprietary numerical-computing environment considered for niche-language support is explicitly dropped since it needs a licensed vendor dependency behind its LSP shim. |
| ADR-064: Doctor default ruleset lands | Three new built-in checks (LICENSE presence, packaging metadata, build-database validity), reusing existing scanner data with no new detection logic. |
| ADR-065: first glob-based (not exact-filename) language manifest lands | Extends language detection beyond one canonical manifest filename per language; ships in the repo but requires explicit per-project opt-in, not compiled in as a default. |
| ADR-066: two formal-methods language manifests land, one earlier claim corrected | Corrects an earlier unverified claim that a standalone LSP server existed for a formal-methods language; both new manifests land with the LSP field honestly absent rather than guessed. |
| ADR-067: a third formal-methods manifest lands with an explicit confidence caveat | Flagged as lower-confidence than its siblings since the exact build invocation wasn't verified against a live install -- stated plainly rather than presented as equally solid. |
| ADR-068: last niche-language manifest lands, closing the original taxonomy | Every tool it depends on confirmed real before writing the manifest -- the first niche addition in the batch needing no correction or caveat. |
| ADR-069: Debugger integration scoped -- two structurally different tracks | One subprocess-owned debug-protocol client for compiled/scripting languages, and a second client that connects out to an already-running host application's own debug port for a browser-embedded-panel case; live-debuggee trust and self-debugging both explicitly left open. |
| ADR-070: a real, exploitable plugin sandbox escape -- fixed | One host-facing plugin function had no path-containment check at all (unlike its sibling), letting any auto-run plugin enumerate file paths anywhere the OS user could read; fixed with the same two-layer containment its sibling already used. |
| ADR-071: three High-severity plugin-hardening findings, fixed as one pass | Plugin discovery gained real path-containment plus fail-closed-on-malformed-manifest behavior; WASM execution gained a real wall-clock deadline and a per-plugin memory cap, both proven against genuine traps. |
| ADR-072: two remaining Low findings from the same review, closed | A manifest-health-check reporting inconsistency fixed; the project's already-correct subprocess trust model documented plainly for end users for the first time. |
| ADR-073: three cleanup findings from a second external review, closed | Stale protocol-naming doc claims corrected; every headless-command error now prints cleanly instead of a raw internal dump; several math crates hardened against degenerate (NaN/Inf/zero-sample) input. |
| ADR-074: six more findings from a third review, fixed | A real symlink race in the repair-write path (fixed via atomic exclusive file creation), a not-yet-wired command-injection risk in the embedded editor, a predictable shared socket path, and unbounded subprocess/host memory and time, all fixed with tests proving the actual mechanism. |
| ADR-075: real trust gate for project-declared command execution | A `direnv`-style trust gate -- per-project, content-hash-pinned, stored outside the project -- now guards every project-declared command path (AI adapter, custom tasks, auto-discovered scripts); fails closed when no terminal exists to prompt on. |
| ADR-076: last untrusted execution path closed; `--version`/`-V` added | A project-local language manifest's declared tasks and LSP binary are now gated the same way as every other declared-command path; `--version`/`-V` added in the same pass. |
| ADR-077: sync-all-panes keybinding pattern completed | Closes the one remaining gap in the sync-all-panes pattern (tick-rate adjustment gets a group-level sibling, matching the live-toggle and snapshot actions that already had one). |
