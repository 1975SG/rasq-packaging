# IDERM -- Security posture and real verification results, compacted

Compact index for the public packaging repo. Canonical detail: `SECURITY.md`, `docs/manual/11_Security.md`, and `docs/reports/` (not part of this doc set).

## Security posture

- **Threat model.** Three trust zones: the Core process (native, user permissions), WASM plugins (Wasmtime component store, no preopened directories/env/args/network), and native children (task/shell/Neovim/Git/LSP/AI command, native process with user permissions). Project data and any external service a child reaches are treated as outside Core's control.
- **Plugin sandbox.** A `doctor-rule`/`repair-recipe`/`view-provider` plugin gets exactly three host functions -- `read-file`, `list-files`, `log` -- all path-canonicalized and rejected if resolved outside the project root, including through a symlink. 256 MiB linear-memory limit, ~2s epoch budget per call. Resource limits reduce impact; they do not prove a plugin is benign.
- **Native execution.** Subprocesses are always spawned argv-array form, never a shell string -- no shell-injection vector exists by construction. A project can still declare `sh`/`bash` as its own program, in which case the script has shell semantics.
- **Trust gate.** Every project-declared command path -- `.iderm/ai.toml`, `.iderm/tasks.toml`, an auto-discovered `stream_*` script, and a project-local `.iderm/languages/*.toml`'s `tasks`/`lsp_binary` -- requires explicit trust, pinned to the declared file's exact content by a SHA-256 hash, stored outside the project. Editing the file invalidates prior trust. Headless use fails closed with no terminal to prompt on; `iderm trust <path>` establishes trust ahead of a scripted/CI run. Full design and hardening history: `Decisions_Compact.md` ADR-070 through ADR-076 (a real plugin-sandbox path-traversal escape found and fixed, three further High-severity plugin-hardening findings, and the trust gate itself).
- **Repair writes.** A repair plugin or AI proposal may create a new file only, under a canonicalized existing parent directory within the project root; an existing destination is always rejected. Interactive Repair requires affirmative confirmation; headless `--apply` is itself the affirmative instruction.
- **Residual risks, stated plainly.** Native children run with the user's OS permissions; Core itself is not sandboxed; plugin resource limits are containment, not a formal isolation proof; project files may change between validation and later external use.
- **Vulnerability reporting.** Through GitHub Security Advisories on the project repository -- private until a fix is published. One maintainer, best-effort acknowledgment, credit given unless anonymity is requested. Out of scope: a third-party tool IDERM starts as a child process, or an issue requiring attacker write-access to the project directory already.

## Real verification results

One compact line per pass -- every result below is from a real build/binary exercised through a real PTY or the real headless CLI, not asserted.

| Pass | Result |
|---|---|
| RHEL 10.2, first pass (pre-built binary, real PTY + synthetic keystrokes) | Every reachable feature passed against real induced data (scanner, Doctor, Git panel, embedded Neovim + live RPC, Repair decline/apply, tree-sitter outline, preview/viewer/inspector panels, LSP graceful-failure paths). Plugin sandbox proven end-to-end (18/19 unit tests). Two UI string typos found and fixed. One real task-runner gap found (target listing assumed conventional names instead of parsing the Makefile) and fixed. |
| RHEL 10.2, second pass (headless CLI + TUI, independent regression pass) | `scan`/`doctor --json`, `ledger record`/`diff` all pass with valid schema-versioned output; plugin finding surfaces identically on the headless and TUI paths. Two real test-harness bugs caught and fixed mid-session (not iderm bugs). |
| Debian 12, first pass (build from source, 2008-era dual-Xeon hardware) | 21/21 tests pass, including a genuine `rust-analyzer` LSP handshake and the Phase 4 plugin sandbox exercised for real. |
| Debian 12, second pass (Phase 5/6 regression, same hardware) | Build clean (4m15s). 123/123 tests pass after building one plugin artifact the suite needs (6 failures on first run were a correct, expected assertion against a missing build artifact, not a bug). Real `rust-analyzer` handshake confirmed again. |
| Zorin (informal pass, pre-built binary, no scripted checklist or automated test run) | Doctor, Repair dry-run, and markdown preview all confirmed working from real screenshots against a bare test project; narrower coverage than the other three platform passes, no issues found within what was exercised. |
| macOS (source snapshot, native build) | 264/264 combined Rust unit/integration tests pass (0 failures, up from 257/260 on an earlier snapshot of the same pass). Real headless CLI (`scan`/`doctor --json`, `ledger record`) and plugin ABI end-to-end proof (`example-doctor-rule.wasm` loaded and run through Wasmtime against the live host) both pass. |
| macOS security review | Manual OWASP-class source review + `cargo audit` (387 dependencies) + empirical proof-of-concept reproduction. One real, exploitable sandbox-boundary bug found and fixed the same day (`host::list_files` path-traversal/absolute-path escape -- see ADR-070); two Low findings (design-correct but under-documented, and a defense-in-depth gap in manifest-entry path validation); zero hand-written `unsafe` code anywhere in scope; zero dependency CVEs (one informational unmaintained-crate advisory, no action needed). |
| 8-hour soak test (real headless CLI under sustained synthetic load) | **PASS**, verdict per ADR-051. 480/480 ticks, zero errors across `scan`/`doctor`/`ledger record`/`ledger diff`/`graph` (48 samples independently verified through a real Graphviz render), three real continuously-running child processes with zero deaths and no memory leak across the full run. |
| DEB packaging (real hardware install, 2008 dual-Xeon Debian 12 box) | Both variants (base and plugins-bundled) build and install cleanly; extracted and root-installed binaries both report the correct version and, for the bundled variant, ship all bundled plugin files at the correct path. Real `sudo dpkg -i` install confirmed working end-to-end against a real, unrelated third-party project already on that machine. |
| RPM packaging (real hardware build, clean RHEL box) | Both packages (base and plugins-bundled subpackage) build and install cleanly once the distro Rust/Cargo toolchain (not a `rustup`-managed one) is present -- `rpmbuild`'s dependency check on this is treated as a real requirement, not bypassed. Debuginfo extraction disabled for the Rust release binary, matching how Rust binaries don't fit rpmbuild's default assumption. |
| Homebrew packaging (real hardware build, clean macOS box) | `--build-from-source --HEAD` install succeeds end-to-end from a real local git-backed tap; confirmed via a real self-scan of the project's own repository and a real multi-pane live-hardware-capture session afterward. |

**Not yet done**: `cargo-deny` dependency/license/advisory audit (config written, never actually run); `lintian`/`rpmlint` package-quality linting (neither tool was installed on the respective test box).
